# Каналы подключения

Модуль до сих пор описывал только то, что видно на фасаде: приборы с монтажными
вырезами (`devices`) и шильды (`labels`). Чем панель питает технологию — какое
оборудование подключается к её клеммам и сколько входов ПЛК это занимает — в
модели отсутствовало, поэтому манометры, термосопротивления подшипников, датчики
вибрации и вообще любые «неотображаемые» подключения выпадали из компоновки.

Для этого у модуля появился третий массив — `channels`. Тип — `ChannelSpec`
в [src/types.ts](../src/types.ts).

**Канал — это точка подключения одного внешнего устройства**, а не сигнал ПЛК.
Станция с преобразователем частоты — один канал, а не десять; манометр — один
канал. Сигналы внутри канала не расписываются построчно, а даются сводкой:
`2 AI, 4 DI, 4 DO`. Из сводки считается загрузка модулей ПЛК, из перечня
каналов — кабельный журнал и спецификация барьеров.

## Где описывать

Каналы панели заполняются в отдельном файле `docs/каналы/<код>.md` — по одному
файлу на код панели, имя файла только код: `45.md`. Файл читает генератор
библиотеки, поэтому это **данные**, а не пояснение: заголовки столбцов менять
нельзя.

**Не** в `src/library/*.json`: эти файлы генерируются, и `npm run gen:library`
их предварительно удаляет. И **не** в `scripts/gen-library.mjs`: там геометрия
фасада. Если каналы панели заданы в обоих местах, генератор откажется писать
библиотеку — источник должен быть один.

Порядок работы:

```bash
npm run channels -- 45           # разбор одного файла: что прочитано, где ошибка
npm run gen:library              # каналы попадают в src/library/45.json
npm run check                    # проверки библиотеки, фотографий и компоновки
```

Ошибки разбора приводят к строке файла:

```
45.md:22: неизвестное устройство «ПЧВ». Допустимо: ПЧ, ЭКМ, датчик, прибор, задвижка, двигатель
45.md:24: сигналы «2 AI, 4 DX»: неизвестный тип сигнала «DX». Допустимо: AI, AO, DI, DO, RTD, TC, RS485, Ethernet
```

## Таблица каналов

Парсер узнаёт таблицу с данными по **первому столбцу** — `Канал`. Любые другие
таблицы в файле (состав модулей ПЛК, пояснения) он не трогает.

| Канал | Устройство | Что подключается | Объект | На фасаде | Сигналы | Ex | Клеммы | Вход ПЛК | Назначение |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| ПЧ1 | ПЧ | ПЧ ABB | 1 | да | 2 AI, 4 DI, 4 DO | нет | 1XT1 | AI1, DI1, DO1 | Станция с ПЧ, насос Н-1 |
| ЭКМ1 | ЭКМ | Электроконтактный манометр | 1 | нет | 1 DI | | XT4 | DI2 | Давление, насос Н-1 |

Здесь два канала одного объекта: станция с ПЧ даёт группу органов управления на
фасаде, её манометр — только вход ПЛК.

### Столбцы

| Столбец | Что писать |
|---|---|
| `Канал` | Обозначение в модуле: `ПЧ1`, `ЭКМ1`, `AI3`. Обязательно, должно быть уникальным |
| `Устройство` | Тип из закрытого списка: `ПЧ`, `ЭКМ`, `датчик`, `прибор`, `задвижка`, `двигатель`. Обязательно |
| `Что подключается` | Конкретное изделие, если оно закреплено: «ПЧ ABB», «ЭКМ-1У», «Метран-55» |
| `Объект` | Номер объекта модуля с единицы — тот же, которым оперирует правило подбора (`cap` в [kinds.mjs](../scripts/kinds.mjs)). Через него канал связан с блоком фасада и его шильдами |
| `На фасаде` | `да` — канал даёт приборы и шильды; `нет` — подключение есть, а на лицевой части его не видно |
| `Сигналы` | Сводка входов и выходов ПЛК: `2 AI, 4 DI, 4 DO`. Одиночный тип без числа читается как одна цепь |
| `Ex` | `Exi` — искробезопасная цепь через барьер; `Exd` — без искрозащиты; `нет` |
| `Барьер`, `Артикул барьера`, `Барьеров` | Барьер или разделитель в цепи: наименование, артикул, количество. Идёт в спецификацию секции |
| `Клеммы` | Клеммник или контакты по РД: `1XT1`, `XT5:1,2` |
| `Вход ПЛК` | Модули или каналы, которые занимает подключение: `AI1, DI1, DO1` |
| `Назначение` | Назначение, если оно закреплено исполнением панели |

Синонимы заголовков: `Тип устройства` = `Устройство`, `Наименование` =
`Что подключается`, `Взрывозащита` = `Ex`, `ПЛК` = `Вход ПЛК`, `Клемма` =
`Клеммы`.

### Правила заполнения

| Правило | Как это работает |
|---|---|
| Столбцы читаются по названию, а не по месту | Порядок любой, ненужные столбцы можно убрать, незнакомые заголовки пропускаются с предупреждением |
| Пустая ячейка и прочерк — «данных нет» | Кроме столбца «На фасаде»: там прочерк читается как «нет» |
| Один канал — одно устройство | Не «восемь дискретных входов ПЧ», а «станция с ПЧ, сигналы 4 DI» |
| Несколько каналов на один объект — норма | У станции свой канал и у её манометра свой, объект у них общий |
| Число сигналов и число каналов не хранятся | Считаются по таблице: сумма сводок и число строк |
| Номер объекта не больше ёмкости модуля | Проверяется по `kinds.mjs`: у модуля 45 объектов 4, у 02 — восемь |

Прозу — откуда взяты данные, что принято по аналогии, чего в выгрузке нет —
писать в том же файле рядом с таблицей: это часть данных, а не черновик.
Образцы: [каналы/45.md](каналы/45.md) — станции с ПЧ и скрытые манометры,
[каналы/02.md](каналы/02.md) — восемь датчиков через барьеры.

## Поля канала в модели

| Поле | Обязательно | Что писать |
|---|---|---|
| `id` | да | Обозначение канала в модуле |
| `kind` | да | Тип устройства из закрытого списка (`DeviceKind`) |
| `device` | нет | Конкретное изделие |
| `object` | нет | Номер объекта модуля, с единицы |
| `facade` | нет | `false` — канала на лицевой части не видно |
| `signals` | нет | Сводка сигналов ПЛК: `{ AI: 2, DI: 4, DO: 4 }` |
| `ex` | нет | `Exi`, `Exd`, `нет` |
| `barrier` | нет | Барьер или разделитель: наименование, артикул, количество |
| `terminal` | нет | Клеммы по РД |
| `plc` | нет | Модули или входы ПЛК |
| `purpose` | нет | Назначение канала |

## Исполнения одной панели

Одна и та же лицевая панель может идти с разной обвязкой: восемь каналов Exi
через барьеры либо восемь Exd без барьеров и без индикации. Это **разные записи
библиотеки со своими кодами**, а не варианты одной записи. Причины:

- код модуля входит в обозначение секции `НТ53.AA.BB.CC.DD` — по обозначению
  должно быть однозначно понятно, что внутри;
- комплект барьеров — это железо на монтажной плите, другая цена и другой
  артикул панели;
- спецификация и кабельный журнал собираются по коду.

Код исполнения присваивается в базе изделий EPLAN, а не придумывается в
конфигураторе. Фотография (или вид по РД) нужна на каждое исполнение — иначе
`check-photos.mjs` сообщит о расхождении библиотеки и папки `Модули`.

## Что уже работает и что нет

| Готово | Ещё нет |
|---|---|
| Тип `ChannelSpec`, поле `channels` у модуля | Лист «Каналы и барьеры» в спецификации XLSX |
| Файлы `docs/каналы/<код>.md` и их разбор | Баланс каналов и загрузка ПЛК в `plan.mjs`, раздел `сигналы` в задании |
| Закрытый список устройств, сводка сигналов | Перечень сигналов и кабельный журнал (этап 5 по ТЗ) |
| Заполнены все панели библиотеки, кроме глухой и 04-1 (03-1 — по аналогии с 03; 05-1 — по схеме `С3_23` выгрузки `+05`, где приборов три) | Состав сигналов панели 04: рабочей документации нет (замечание 35); каналы панели 04-1 — описана по фотографии (замечание 41); каналы 03-1 требуют подтверждения (замечание 42) |
| Проверка каналов в `check-library.mjs`, сверка объектов с `kinds.mjs` | Выгрузка файлов каналов в XLSX для инженера EPLAN |

Что осталось получить от инженера EPLAN: артикулы барьеров панели 02, номера
контактов клемм по всем панелям, заполненные карты ПЛК, документацию панели 04 и
взрывозащиту цепей там, где она не указана. Открытые вопросы — в
[Замечания к EPLAN.md](Замечания%20к%20EPLAN.md).

Сводка по панелям — в справочнике навыка (`npm run gen:library-table`) и в отчёте
`npm run check`: он же печатает, какие поля каналов ещё не заполнены.
