# AI collaboration rules — ООО «Нефтяные технологии» · проект НТ53

## Среда выполнения (модель v2.0 — подробно в `AI/AI_COLLAB.md`)

- **Рабочее дерево — локальная Git-копия репозитория** `C:\NT\Шкафы АСУТП НТ53`: код приложения,
  `AI/`, `CLAUDE.md`. Claude Code и dev-сервер запускаются здесь; локально Bash стабилен.
- **Synology** (`\\NT1`, диск `P:`) — общий файловый сервер бинарников (выгрузка EPLAN, фотографии
  панелей, крупные изображения) и хост Git-сервера Gitea (`http://NT1:3000`, `NT/asutp-nt53`).
  **При работе с путями на `P:` — PowerShell/Python** (Bash на сетевых путях нестабилен);
  `Move-Item` к свежесозданным папкам на `P:` не применять.
- Путь к бинарникам на Synology скрипты берут из переменной `NT_ASUTP_DATA`
  (по умолчанию `P:\Projects\Шкафы АСУТП НТ53`) или файла `AI/scripts/local.config` (в `.gitignore`).
- Node.js — для приложения и скриптов (`npm`, `node`). Если политика PowerShell блокирует `npm.ps1`,
  использовать `npm.cmd` либо `node scripts/…` напрямую (см. корневой `README.md`).
- Контекст проекта хранится в папке `AI/` и в корневом `README.md`, версионируется в Git
  (`git pull`/`push`). Локального хранения контекста вне проекта быть не должно.
- При начале новой сессии: `git pull`, затем читать `AI/AI_HANDOFF.md`, `AI/AI_RULES.md`.

## Библиотека модулей и выгрузки (правила проекта)

- **`src/library/*.json` не править вручную** — они генерируются. Менять `scripts/gen-library.mjs`,
  затем `npm run gen:library && npm run check`. Если модулю нужно новое поле — порядок в
  `docs/Модель данных модуля.md`.
- Каналы подключения — в `docs/каналы/<код>.md` (единственный источник), не дублировать в генераторе.
- Состав и коды панелей — по фотографиям и выгрузке EPLAN в папке `Модули` (на `P:`), не выдумывать.
- **После правки библиотеки** перегенерировать справочник навыка:
  `npm run gen:library-table -- --out="P:/Projects/_Tools/claude-plugins/plugins/asutp-sections/skills/asutp-sections/references/library.md"`.
- Фирменная рамка PDF и логотип — из шаблона AI-пакета ООО «НТ» (`npm run gen:frame`), не
  вычерчивать по ГОСТ заново.
- Перед завершением задачи по коду прогонять проверки: `npm run check` (и при правке выгрузок —
  `npm run check:pdf` / `npm run check:dxf`).

## Фирменное оформление (ООО «НТ»)

- Выгрузки (PDF со штампом, спецификации) и любые документы оформляются от имени
  **ООО «Нефтяные технологии»**. Реквизиты, наименование и логотип — из
  `AI/company/Реквизиты_ООО_НТ.md`. Не вводить реквизиты вручную из памяти.
- Полное наименование — «Общество с ограниченной ответственностью „Нефтяные технологии"»,
  краткое — ООО «Нефтяные технологии». При изменении реквизитов — обновить `AI/company/…` и
  зафиксировать в `DECISIONS.md`.

## Общие правила работы

- Работать только внутри проектной папки; не использовать старые локальные пути вне проекта.
- Не удалять и не перезаписывать файлы без явного понимания последствий; не затирать ручные правки.
- Если задача просит только анализ, объяснение или план — не менять файлы, пока нет явного
  разрешения. Перед автоматическим массовым изменением — сначала план и подтверждение.
- Перед массовыми изменениями данных/файлов делать резервную копию в `AI/backups/`.
- Язык кода-комментариев и документации — русский. Формат дат в служебных файлах — `ГГГГ-ММ-ДД`.

## Работа с версиями и чужими изменениями

- Не откатывать чужие изменения; не выполнять `git reset --hard` и другие destructive-команды
  без прямого запроса.
- Текст и код (`AI/`, `src/`, `scripts/`, `docs/`) синхронизируются через Git — конфликты решает
  merge/PR. Правило «один редактор на файл» относится к бинарникам на Synology, которые Git не сливает.
- Перед изменением файла, который мог правиться вручную, перечитать его актуальное состояние.

## Когда обновлять этот пакет

Обновлять файлы `AI/`, если: появилось постоянное проектное правило; изменился порядок запуска
скриптов или сборки; добавилось новое направление; обнаружен риск для командной работы; ручная
правка стала эталоном; изменились реквизиты или фирменное оформление ООО «НТ».
