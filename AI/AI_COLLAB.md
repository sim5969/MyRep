# Коллективная работа над проектом (v2.0) — ООО «Нефтяные технологии»

Инструкция по командной работе над проектом **НТ53 «Конфигуратор секций АСУ ТП»** (стандарт
ООО «НТ», версия **2.0**).

**Модель v2.0:** **Synology** (NAS `\\NT1`, диск `P:`) — общий файловый сервер бинарников и хост
централизованного Git; **Git** (self-hosted **Gitea** на этом же NAS) — единый репозиторий кода и
текстовой части проекта. У каждого участника — **свой Git-аккаунт**, **свой Claude-аккаунт** и
**своя локальная Git-копия**, в которой он и работает. Тяжёлые бинарники (выгрузка EPLAN,
фотографии панелей, крупные изображения) остаются на Synology и в Git не попадают.

> Особенность этого проекта: он **программный**, поэтому в Git ведётся весь исходный код
> приложения (не только пакет `AI/`). На Synology остаётся лишь входной бинарь — выгрузка EPLAN и
> фотографии панелей в папке `Модули`.

## 1. Архитектура: два хранилища

```
┌──────────────────────────────────────────────────────────────┐
│  Synology NAS (\\NT1, диск P:)                                 │
│  ─ Git-сервер Gitea (http://NT1:3000, SSH 2222)  ← центр Git   │
│  ─ Файловый сервер бинарников (P:\Projects\Шкафы АСУТП НТ53):  │
│      • выгрузка EPLAN  Модули\Макросы V25.02 (…)\  (DXF, 77 МБ)│
│      • фотографии панелей  Модули\*.jpg                        │
│      • крупные исходные изображения                            │
└───────────────▲───────────────────────────▲──────────────────┘
        git push │ git pull                  │ чтение бинарников
                 │                           │ (по настраиваемому пути NT_ASUTP_DATA)
   ┌─────────────┴─────────┐     ┌───────────┴──────────────────┐
   │ ПК участника 1        │     │ ПК участника 2               │  …
   │ C:\NT\Шкафы АСУТП НТ53 │     │ C:\NT\Шкафы АСУТП НТ53        │
   │ src/ scripts/ AI/ …   │     │ src/ scripts/ AI/ …          │
   │ Claude Code + dev      │     │ Claude Code + dev            │
   │ РАБОТАЮТ здесь         │     │ РАБОТАЮТ здесь               │
   └───────────────────────┘     └──────────────────────────────┘
```

- **Локальная копия** (`C:\NT\Шкафы АСУТП НТ53`) — рабочее дерево: код приложения (`src/`,
  `scripts/`, `tests/`, `docs/`), пакет `AI/`, `CLAUDE.md`. **Claude Code и dev-сервер (Vite)
  запускаются именно здесь** — работа локальная, поэтому быстро, Bash стабилен, нет сетевых сбоев.
- **Synology (`P:`)** — только бинарники и входные данные, а также сам Git-сервер. Код на `P:` не
  дублируется: единственный источник его истории — Git.

## 2. Что где лежит

| Что | Где | В Git? |
|---|---|:---:|
| Код приложения (`src/`, `scripts/`, `tests/`, `docs/`) | локальный клон | ✅ |
| Библиотека модулей `src/library/*.json` (генерируется) | локальный клон | ✅ |
| Пакет `AI/` (контекст, правила, решения), `CLAUDE.md` | локальный клон | ✅ |
| Конфигурация сборки (`package.json`, `tsconfig.json`, `vite.config.ts`), `.gitignore` | локальный клон | ✅ |
| Выгрузка EPLAN `Модули\Макросы V25.02 (…)\` (DXF) | Synology `P:` | ❌ |
| Фотографии панелей `Модули\*.jpg` | Synology `P:` | ❌ |
| Крупные исходные изображения в корне | Synology `P:` | ❌ |
| `node_modules/`, `dist/`, `AI/backups/`, бинарные отчёты | локально | ❌ |

Состав Git обеспечивает корневой `.gitignore` (whitelist: в репозиторий попадает только
перечисленный код и `AI/` без `backups/` и бинарных отчётов; папка `Модули`, `node_modules` и
сборочные артефакты отсекаются).

## 3. Git-сервер (Gitea на Synology)

- **Адрес:** `http://NT1:3000` (веб-интерфейс), git-по-SSH — порт `2222`.
- **Организация:** `NT`; **репозиторий:** `NT/asutp-nt53` (приватный).
- **Движок:** Gitea (self-hosted в Container Manager на NAS).
- **Свободная регистрация отключена** — аккаунты заводит только администратор.

Если `NT1` не резолвится — использовать IP NAS (`http://<IP>:3000`) и тот же IP в URL клонирования.

## 4. Роли и доступы

| Роль | Ответственность | Доступ в Gitea |
|---|---|---|
| **Ведущий разработчик** | отвечает за приложение и библиотеку модулей | Запись (Write) |
| **Исполнитель** | правит код своего направления, `AI/`, скрипты | Запись (Write) |
| **Проверка / ревью** | комментирует, ревьюит PR | Чтение (Read) |
| **Администратор сервера** | ведёт Gitea, аккаунты, доступы, бэкапы | Site Admin |

Доступ выдаётся на репозитории `NT/asutp-nt53 → Настройки → Соавторы` либо через команды
организации `NT`.

## 5. Локальная копия и связь с бинарниками

Каждый участник держит **одну** локальную копию и работает в ней:

```powershell
git clone http://NT1:3000/NT/asutp-nt53.git "C:\NT\Шкафы АСУТП НТ53"
cd "C:\NT\Шкафы АСУТП НТ53"
npm install
```

Приложение и большинство скриптов работают только с кодом внутри клона. Скрипты, которым нужна
выгрузка EPLAN и фотографии (`rd-facade`, `rd-spec`, `check-photos`), читают их с Synology по
**настраиваемому пути**:

- Корень бинарников задаётся переменной окружения **`NT_ASUTP_DATA`**; значение по умолчанию —
  `P:\Projects\Шкафы АСУТП НТ53`.
- Альтернатива без переменной — файл **`AI/scripts/local.config`** (в `.gitignore`, в репозиторий
  не попадает):
  ```ini
  # локальный, не в Git
  NT_ASUTP_DATA=P:\Projects\Шкафы АСУТП НТ53
  ```

Выгрузка панелей 48/49 и разбор новых модулей выполняются по DXF из `NT_ASUTP_DATA\Модули\…`.

## 6. Дисциплина работы с файлами

**Код и текст (в Git):**
- Изменения кода, `AI/` и скриптов — через ветки и Pull Request (Gitea хранит историю). Конфликты
  решает `git merge`/`rebase`, а не «договориться, кто открыл файл».
- Перед работой — `git pull`. Перед завершением этапа — `npm run check`, затем `commit`/`push`.

**Бинарники (на Synology, слияния нет):**
- **Один редактор на файл** во время правки. Перевыгрузку EPLAN в `Модули` согласовывать.

**Общее правило:**
- `src/library/*.json` собираются генератором — править **генератор** (`scripts/gen-library.mjs`),
  а не итоговый JSON: при пересборке ручные правки затрутся.

## 7. Координация — через артефакты пакета `AI/`

`AI/` — **общая память проекта**; синхронизируется через Git (`pull`/`push`), а не копированием.

- `AI/AI_HANDOFF.md` — «передача смены»: после этапа обновлять состояние и ближайшие шаги.
- `AI/DECISIONS.md` — журнал устойчивых решений; спорные вопросы — сюда, с датой.
- `AI/AI_RULES.md` — единые обязательные правила.

## 8. Онбординг нового участника

1. **Аккаунты.** Администратор заводит участнику аккаунт в **Gitea** и выдаёт доступ к
   `NT/asutp-nt53`. У участника — **свой Claude-аккаунт**.
2. **Доступ к Synology.** Проверить, что смонтирован диск `P:` (`\\NT1`).
3. **Git на ПК.** Установить Git и задать идентификацию:
   ```powershell
   git config --global user.name "Имя Фамилия"
   git config --global user.email "you@company.ru"   # почта совпадает с аккаунтом Gitea
   ```
4. **Локальная копия.** Клонировать репозиторий (раздел 5) в `C:\NT\Шкафы АСУТП НТ53`, выполнить
   `npm install`. При необходимости задать `NT_ASUTP_DATA` или `AI/scripts/local.config`.
5. **Открыть в IDE именно локальную копию** и запускать Claude Code / `npm run dev` там.
6. **Прочитать при старте:** `CLAUDE.md`, `AI/README.md`, `AI/AI_RULES.md`, `AI/AI_HANDOFF.md`,
   корневой `README.md` и **эту инструкцию**.

## 9. Ритм команды

- **Начало сессии:** `git pull` → прочитать `AI_HANDOFF.md`.
- **Во время работы:** ветка на задачу; бинарники — «один редактор на файл».
- **Конец этапа:** `npm run check`; обновить `AI_HANDOFF.md`; устойчивые решения — в `DECISIONS.md`;
  `commit` + `push`, при потребности в ревью — Pull Request.

## Приложение А. Установка и обслуживание Gitea на Synology

Сервер общий для всех проектов ООО «НТ» (тот же, что для `NT/suhodol` и др.). Полный порядок
установки и обслуживания Gitea в Container Manager — в `AI/AI_COLLAB.md` проекта «Суходол»
(`P:\Projects\Суходол\AI\AI_COLLAB.md`, Приложение А). Кратко:

- Container Manager (DSM 7.2+) → проект `gitea`, образ `gitea/gitea`, тома `/volume1/docker/gitea/data`,
  порты `3000:3000` и `2222:22`, `TZ=Europe/Samara`.
- Регистрация отключена (`DISABLE_REGISTRATION = true`), аккаунты заводит админ.
- Бэкап — резервировать `/volume1/docker/gitea/data` в плане резервного копирования NAS.

## Приложение Б. Команды Git (повседневная работа)

**Перенос кода на сервер (однократно, выполнено при заведении репозитория):**
```powershell
git -C "C:\NT\Шкафы АСУТП НТ53" remote add origin http://NT1:3000/NT/asutp-nt53.git
git -C "C:\NT\Шкафы АСУТП НТ53" push -u origin --all
git -C "C:\NT\Шкафы АСУТП НТ53" push origin --tags
```

**Клонирование (каждый участник):**
```powershell
git clone http://NT1:3000/NT/asutp-nt53.git "C:\NT\Шкафы АСУТП НТ53"
cd "C:\NT\Шкафы АСУТП НТ53"
npm install
```

**Ежедневная работа (ветки + ревью):**
```powershell
git pull
git switch -c feature/задача
# ... правки в src/, scripts/, AI/ ...
npm run check
git add -A
git commit -m "Что изменено"
git push -u origin feature/задача     # затем Pull Request в Gitea → ревью → merge
git switch master
git pull
```

Примечания:
- Аутентификация в Gitea — по логину/**токену** (Settings → Applications) либо по **SSH-ключу**
  (`ssh://git@NT1:2222/NT/asutp-nt53.git`). Токен/ключ надёжнее пароля.
- Рабочая копия — локальная (`C:\NT\Шкафы АСУТП НТ53`), поэтому `.git` не лежит на сетевом диске.
- В Git — код и текст (обеспечивает `.gitignore`); бинарники и выгрузка EPLAN — на Synology.
