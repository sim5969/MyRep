# Рабочий процесс с AI — ООО «Нефтяные технологии»

## Перед началом работы

1. Открыть в IDE **локальную Git-копию** репозитория (`C:\NT\Шкафы АСУТП НТ53`) и выполнить
   `git pull`. Claude Code запускать в этой папке.

   ```text
   C:\NT\Шкафы АСУТП НТ53   (клон репозитория NT/asutp-nt53; бинарники — на Synology P:)
   git pull
   ```

2. Передать AI следующие контекстные файлы:
   - `AI/README.md`;
   - `AI/AI_PROJECT_CONTEXT.md`;
   - `AI/AI_RULES.md`;
   - `AI/AI_HANDOFF.md`;
   - профильный контекст задачи из `AI/context/`.

3. Уточнить режим работы:
   - только анализ;
   - подготовить план;
   - выполнить правки;
   - создать новую выгрузку;
   - обновить правила.

## Безопасный порядок для задач обработки данных

Стандартный безопасный порядок:

1. Прочитать профильный контекст направления из `AI/context/`.
2. Прочитать актуальную структуру рабочего файла (Excel/Word/БД).
3. Выполнить анализ без записи.
4. Сформировать отчёт: что можно сделать уверенно, что требует ручной проверки.
5. Дождаться команды пользователя на запись.
6. Перед записью создать резервную копию рабочего файла в `AI/backups/`.
7. Записать изменения, сохранив ручные колонки, данные, формулы и стили.
8. Сформировать отчёт проверки в `AI/reports/`.
9. Обновить правила, если появились новые устойчивые решения.

## Для нескольких участников

> Полная инструкция по командной работе v2.0 (Synology + централизованный Git, роли, онбординг) —
> в `AI/AI_COLLAB.md`.

- Текст и код (`AI/`, скрипты) — через ветки и Pull Request в Gitea; конфликты решает merge.
- Правило «один редактор на файл» относится к бинарникам (`.docx/.xlsx`) на Synology — не открывать
  один и тот же бинарный файл для массовой записи несколькими участниками одновременно.
- Перед обработкой согласовать, кто владеет бинарным файлом на время операции.
- После ручных правок сообщать AI, какие строки/объекты были изменены и нужно ли обновить
  правила.
- После завершения этапа обновлять `AI_HANDOFF.md` и, при необходимости, `DECISIONS.md`.

## Что просить у AI

Хорошие формулировки:

```text
Изучи файл, ничего не меняй, дай отчёт.
Объясни план, не запускай обработку без моей команды.
Сделай резервную копию и запусти только этот скрипт.
Обнови правила на основе ручных правок, файл не трогай.
```

Нежелательные формулировки:

```text
Приведи всё в порядок.
Обнови как обычно.
Сделай по аналогии.
```

Для командной работы лучше явно указывать файл, лист, объект и разрешение на запись.
