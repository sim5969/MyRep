# Памятка по Git для участника — проект НТ53 «Конфигуратор секций АСУ ТП»

Короткая инструкция, как работать с репозиторием. Подробно — `AI/AI_COLLAB.md`.

## Что в Git, а что нет
- **В Git:** весь код приложения (`src/`, `scripts/`, `tests/`, `docs/`), библиотека
  модулей `src/library/*.json`, фотографии панелей `Модули\*.jpg` с `README.md`, пакет `AI/`,
  `CLAUDE.md`, конфигурация сборки. Работаем в **локальной копии** `C:\NT\Шкафы АСУТП НТ53`.
- **Не в Git (на Synology):** выгрузка EPLAN `Модули\Макросы V25.02 (…)\` (DXF), сборка `dist/`,
  книга `Модули НТ53.xlsx`, крупные изображения — на `P:`. Лишнее отсекает `.gitignore`.

## Однократная настройка (один раз на компьютере)
```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "you@company.ru"    # та же почта, что в аккаунте Gitea
git clone http://NT1:3000/NT/asutp-nt53.git "C:\NT\Шкафы АСУТП НТ53"
cd "C:\NT\Шкафы АСУТП НТ53"
npm install
```
При первом `push`/`pull` ввести логин Gitea и **токен** (Gitea → аватар → Settings →
Applications → Generate New Token, право `write:repository`).

Если скриптам разбора DXF нужна выгрузка EPLAN, задать путь к бинарникам на Synology —
переменную `NT_ASUTP_DATA` или файл `AI/scripts/local.config` (по умолчанию
`P:\Projects\Шкафы АСУТП НТ53`).

## Ежедневный цикл
```bash
git pull                      # 1. забрать свежее с сервера
# ... правки в src/, scripts/, AI/ ...
npm run check                 # 2. прогнать проверки (библиотека, геометрия, подбор)
git status                    # 3. посмотреть, что изменилось
git add -A                    # 4. добавить изменения
git commit -m "Что сделано"   # 5. зафиксировать с понятным сообщением
git push                      # 6. отправить в Gitea
```
Одной строкой: **`git pull` → работа → `npm run check` → `git add -A` → `commit` → `git push`**.

## Ветка и ревью (когда нужна проверка коллегой)
```bash
git switch -c feature/задача        # ветка на задачу
# ... git add -A / git commit -m "..." ...
git push -u origin feature/задача   # отправить ветку
```
Затем в вебе Gitea открыть **«Запрос на слияние» (Pull Request)** → коллега смотрит → **Merge**.
После слияния:
```bash
git switch master
git pull
```

## Конфликты
Если при `git pull`/merge Git сообщил о конфликте — открыть подсвеченные файлы, оставить нужный
вариант (между маркерами `<<<<<<<`, `=======`, `>>>>>>>`), затем `git add <файл>` и `git commit`.

## Правила
- **Код и текст в Git; бинарники и выгрузка EPLAN — на Synology**, их не коммитить.
- `src/library/*.json` **не править вручную** — они генерируются (`npm run gen:library`).
- Перед `push` — `npm run check`; после этапа — обновить `AI_HANDOFF.md`.
- **PowerShell:** команды по одной; `&&` не работает — использовать `;` или отдельные строки.

## Полезные команды
```bash
git log --oneline -10         # последние 10 коммитов
git diff                      # что изменено, но ещё не закоммичено
git switch <ветка>            # переключиться на ветку
git restore <файл>            # откатить незакоммиченные правки в файле
```
Историю, различия и Pull Request удобно смотреть в вебе: `http://NT1:3000/NT/asutp-nt53`.
