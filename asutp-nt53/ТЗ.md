# Техническое задание
## Веб-конфигуратор внешнего вида секций АСУ ТП (НТ53)

Версия 1.1 · 21.08.2026 · статус: черновик к согласованию

Изменение 21.08.2026: терминология приведена к принятой у заказчика. Отдельный корпус
называется **секцией** и обозначается `SEC1`, `SEC2`, …; ряд секций — **комплексом секций
управления (КСУ)**. Прежде корпус назывался шкафом, а ряд — секцией.

---

## 1. Назначение и цель

Веб-приложение для сборки внешнего вида (фасада) секций АСУ ТП из готовых вставных модулей и автоматического получения:

- обозначения (кода) секции и её номера в комплексе;
- чертежа вида на фасад;
- спецификации модулей;
- таблицы надписей (маркировки) для изготовления шильдов.

Цель — исключить ручную сборку фасада в CAD и ручной набор маркировки, свести проектирование типовой секции к выбору 4 модулей из библиотеки и правке надписей.

---

## 2. Термины

| Термин | Значение |
|---|---|
| **Комплекс секций управления (КСУ)** | Ряд секций, стоящих вплотную. Обозначение по умолчанию `КСУ1` |
| **Секция** | Отдельный корпус 2200×600×600 мм с 5 слотами. Обозначение SEC1…SECN по порядку в комплексе |
| **Слот** | Посадочное место под модуль. Слоты 1…5 сверху вниз |
| **Модуль (панель)** | Готовый неизменяемый вставной блок с приборами на лицевой панели |
| **Устройство** | Прибор на лицевой панели модуля: индикатор, лампа, переключатель, панель оператора |
| **Надпись** | Текстовое поле на фасаде (обычно 2 строки) над устройством или группой |
| **Код модуля** | Двузначный код из библиотеки, участвующий в обозначении секции |

## 3. Конструктив

### 3.1 Секция

| Параметр | Значение |
|---|---|
| Габарит В×Ш×Г | 2200 × 600 × 600 мм |
| Количество слотов | Строго 5 |
| Слот 1 (верхний) | Высота 400 мм. Присутствует всегда, тип не меняется |
| Слоты 2…5 | Высота 250 мм каждый |
| Суммарная высота проёма | 400 + 4 × 250 = **1400 мм** |
| Крепление модулей | Собственный конструктив (не 19 дюймов) |

Слоты нумеруются сверху вниз: 1 — верхний (400 мм), 5 — нижний.

### 3.2 Слот 1 — панель сигнализации и индикации (код `01`)

Неизменяемая панель 540 × 400 мм, присутствует во всех секциях:

- заголовок панели («Сигнализация аварийного уровня»);
- зелёная лампа Ø22 «Питание ~220В»;
- линейка сигнальных ламп Ø22 (до 12 шт.) с индивидуальной двухстрочной надписью над каждой;
- 8 цифровых индикаторов с двухстрочной надписью над каждым.

Редактируются только тексты надписей. Код `01` в обозначении секции не выводится.

### 3.3 Слоты 2…5

Заполняются модулями из библиотеки. Пустой слот закрывается заглушкой.
Состав модуля неизменяем; редактируются только текстовые поля, помеченные в описании модуля как редактируемые.

### 3.4 Цветовая семантика ламп (фиксированная)

| Цвет | Значение |
|---|---|
| Зелёный | Питание, норма, готовность |
| Красный | Авария, аварийный уровень |
| Синий | Прочая сигнализация |
| Жёлтый | Предупреждение |
| Белый | Состояние / прочее |

Цвет задаётся типом модуля и пользователем не меняется.

## 4. Обозначение (маркировка)

### 4.1 Код секции

Формат: `НТ53.AA.BB.CC.DD`

- `НТ53` — номер разработки, константа;
- `AA` — код модуля в слоте 2;
- `BB` — код модуля в слоте 3;
- `CC` — код модуля в слоте 4;
- `DD` — код модуля в слоте 5.

Пример из натуры: `НТ53.47.47.45.03` — слоты 2 и 3 заняты модулем 47, слот 4 — модулем 45, слот 5 — модулем 03 («панель управления частотными преобразователями, 4 шт.»).

Код собирается **автоматически** при изменении состава слотов и выводится в заголовке секции, на чертеже и на шильде «Секция автоматизации».

Заглушка получает собственный код (по умолчанию `00`).

### 4.2 Обозначение секции

`SEC1`, `SEC2`, … `SECN` — по порядку секций в комплексе слева направо. Отображается на фасаде
и в шапке чертежа. Комплекс обозначается отдельно (`КСУ1`) и выводится на первом листе альбома.

### 4.3 Позиционные обозначения устройств

Формат `<слот>.<номер устройства в модуле>`: `1.1`, `1.2`, `2.1`, `2.2` …
Нумерация внутри модуля — слева направо, сверху вниз. Полное обозначение в спецификации: `КСУ1 / SEC1 / НТ53.47.47.45.03 / 3.4`.

### 4.4 Надписи

Надписи — свойство конкретного экземпляра модуля в конкретной секции, задаются индивидуально. Типовой шаблон — две строки:

```
строка 1: назначение параметра   («Уровень взлива»)
строка 2: объект                 («Ёмкость Е-4 V=100м³»)
```

Ограничения по длине строки задаются описанием модуля (исходя из ширины поля шильда). При превышении — предупреждение в редакторе.

Способ нанесения: печать на плёнке ORACAL, сверху защитная прозрачная плёнка, обрезка по контуру и наклейка на самоклеящуюся основу плёнки ORACAL. На этапе 2 выгружается таблица надписей и раскладка с контурами обрезки.

## 5. Стартовая библиотека модулей

Единственный источник состава и кодов панелей — фотографии в папке `Модули`
(имя файла: «<код> <наименование>.jpg»). Перечень панелей из EPLAN не используется:
по решению заказчика он выводится из обращения.
Соответствие библиотеки и папки фотографий проверяется скриптом `scripts/check-photos.mjs`.

Если для панели есть рабочая документация из EPLAN
(`Модули/Макросы V25.02 (Platform_2026)/==КД/=ОП/.SEC1/+<код>`), состав, артикулы
и геометрия берутся из неё, а фотография остаётся для сверки внешнего вида. Так
собраны панели 01, 03, 05, 15, 45 и 65 — см. `docs/Рабочая документация — данные панелей.md`.
Расхождения количества приборов между именем фотографии и библиотекой показывает
`scripts/check-photos.mjs`. Несоответствия самой выгрузки EPLAN ведутся в
`docs/Замечания к EPLAN.md` и передаются инженеру как задание на правку проекта.

### 5.3 Описание модуля в библиотеке (структура)

```jsonc
{
  "code": "02",
  "name": "Панель с индикаторами, 8 шт.",
  "slotHeight": 250,          // 250 или 400
  "allowedSlots": [2, 3, 4, 5],
  "price": null,              // заполняется позже
  "devices": [
    {
      "id": "1",               // номер прибора → позиционное обозначение «слот.номер»
      "type": "indicator",     // indicator | lamp | switch | opPanel | meter | device
      "x": 20, "y": 60,        // мм от левого верхнего угла лицевой панели
      "w": 96, "h": 48,
      "color": null,           // для ламп: green | red | blue | yellow | white
      "name": "Индикатор цифровой щитовой 96×48"
    }
  ],
  "labels": [
    {
      "id": "L1",
      "x": 6, "y": 44, "w": 124,
      "lines": 2,
      "maxChars": [24, 24],
      "default": ["Температура", "Ёмкость"],
      "editable": true,
      "align": "center",
      "fontSize": 3.2
    }
  ]
}
```

Библиотека хранится в виде набора JSON-описаний, отрисовка — SVG-примитивами по координатам. Добавление нового модуля = добавление JSON-файла, без изменения кода приложения.

## 6. Функциональные требования

### 6.1 Редактор

1. Создание проекта: наименование объекта, шифр, количество секций в комплексе.
2. Полотно с фасадом комплекса в масштабе, секции слева направо, подписи SEC1…SECN.
3. Каталог модулей слева: превью, наименование, код, фильтр по типу.
4. Установка модуля в слот перетаскиванием или двойным кликом. Слот 1 заблокирован для замены.
5. Панель свойств справа: код модуля, перечень устройств, редактирование разрешённых надписей с контролем длины.
6. Автоматический пересчёт кода секции при любом изменении состава.
7. Клонирование секции (с надписями или без), перестановка секций в комплексе, удаление.
8. Пресеты — сохранённые типовые секции («секция насосной станции»), установка пресета одним действием.
9. Отмена/повтор действий (undo/redo), автосохранение в браузере.
10. Масштабирование и панорамирование полотна, режимы «весь комплекс» / «одна секция».

### 6.2 Валидация

- Слот 1 всегда занят панелью `S1`, замена и удаление запрещены.
- Слоты 2…5: допускаются только модули с `slotHeight = 250`.
- Пустой слот автоматически заполняется заглушкой `00` при выгрузке документов.
- Превышение длины надписи — предупреждение, не блокирующее.
- Дубликаты обозначений устройств — ошибка.

### 6.3 Выходные документы

| Документ | Формат | Содержание |
|---|---|---|
| Чертёж вида на фасад | PDF, **А3 в фирменной рамке ООО «НТ» с большим штампом**, масштаб 1:10 | Лист на комплекс + лист на каждую секцию, с кодом секции и позиционными обозначениями. Сделано: рамка и штамп берутся из шаблона AI-пакета организации; позиционные обозначения — в таблице «Приборы на фасаде», так как при 1:10 буква на фасаде выходит 0,2 мм |
| Альбом комплекса | PDF | Все листы одним файлом: лист комплекса, на каждую секцию лист фасада и лист таблицы редактируемых надписей. Сделано |
| Чертёж фасада | DXF | Векторная геометрия в мм, слои: контур, приборы, надписи |
| Спецификация | XLSX | КСУ → секция → слот → код и наименование модуля → кол-во → цена → сумма |
| Таблица надписей | XLSX / CSV | Секция, слот, позиция, строка 1, строка 2 — для изготовления шильдов |
| Проект | JSON | Полное состояние проекта, загрузка обратно в конфигуратор |
| Коды модулей для EPLAN | CSV / XML | Задел: перечень секций и кодов модулей для импорта в EPLAN |

Стоимость ведётся **на уровне модуля** (поле `price`), справочник артикулов и покомпонентная смета не требуются.

## 8. Нефункциональные требования

- Язык интерфейса — только русский.
- Вся геометрия — в миллиметрах, единая система координат от левого верхнего угла секции.
- Рендер — схематичный вектор (SVG): рамки приборов, круги ламп, семисегментные поля, тексты. Фотореалистичные изображения не используются.
- 3D-вид на текущем этапе не требуется.
- Работа в актуальных Chrome / Edge, разрешение от 1440×900.
- Отклик редактора при перетаскивании модуля — без заметных задержек на комплексе из 6 секций.

## 9. Технический стек

**Этап 1 (без сервера):**

- React 18 + TypeScript + Vite;
- рендер фасада — SVG (собственные компоненты по описаниям модулей);
- состояние — Zustand, история undo/redo;
- экспорт: PDF — jsPDF + svg2pdf, XLSX — ExcelJS, DXF — генератор на основе dxf-writer;
- хранение — JSON-файл + localStorage;
- библиотека модулей — JSON-файлы в репозитории.

**Этап 2 (сервер):**

- бэкенд Node/Fastify либо Python/FastAPI, БД PostgreSQL;
- авторизация, роли (инженер / администратор библиотеки);
- общая библиотека модулей и пресетов, версионирование проектов;
- ссылка на просмотр проекта для согласования.

Архитектура этапа 1 закладывается так, чтобы переход на сервер не требовал переписывания редактора: доступ к библиотеке и проектам — через слой репозитория с двумя реализациями (локальная / сетевая).

## 11. Открытые вопросы

1. **Коды модулей.** Реальные коды (47, 45, …) отличаются от условных `03`…`11` в разделе 5. Нужен фактический перечень кодов с наименованиями.
2. ~~**Компоновка 8 индикаторов в панели слота 1.**~~ Закрыто: рабочая документация (лист `+01/…&ВО_8`) подтверждает 2 ряда по 4, вырезы 92 × 45 шагом 117, оси рядов 224,3 и 324,3.
3. **Артикулы ламп и переключателей EMAS.** Нужны для панелей 02 и 04 — единственных, что остались собранными по фотографиям. В панелях с рабочей документацией применены реальные артикулы: IEK ADDS (01, 15, 45, 65), Schneider ZB5 (45, 65), EKF XB4 (15, 65).
4. ~~**Ширина лицевой панели слота 1.**~~ Закрыто: верна 540, компоновка модуля в EPLAN будет поправлена (в выгрузке 506 × 399).
5. ~~**Панель 05: 3 или 4 прибора; панель 65: задвижки или ПЧ.**~~ Закрыто: панель 05 — четыре ГАММА-8М (в EPLAN будет поправлено); панель электрозадвижек переназначена с 65 на **15**, выгрузка переделана. Код 65 остался за исполнением «ПЧ 2 шт. + электрозадвижки 2 шт.», выгрузка на него получена и панель собрана по РД.

## 12. Критерии приёмки

Работа принимается, если для комплекса из 6 секций конфигуратор позволяет:

1. собрать фасад из модулей библиотеки за время не более 10 минут;
2. получить корректный код каждой секции вида `НТ53.AA.BB.CC.DD`;
3. отредактировать все надписи на фасаде;
4. выгрузить PDF-альбом А3, DXF, спецификацию XLSX и таблицу надписей;
5. сохранить проект в JSON и открыть его повторно без потери данных.
