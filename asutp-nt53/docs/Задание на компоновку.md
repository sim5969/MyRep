# Формат задания на компоновку

Файл JSON в UTF-8. Читается командой `scripts/plan.mjs` конфигуратора НТ53.
Ключи русские — задание читает и правит инженер.

Формат откалиброван по реальному проекту: задание, собранное из его компоновки,
воспроизводит все 4 секции и 160 надписей без расхождений. Этот эталон содержит
данные объекта заказчика и в Git не хранится — он лежит в папке `tests\plan\`
корня бинарников (`NT_ASUTP_DATA`) и подхватывается `npm run check:plan`.
Учебный образец в Git — `tests/plan/пример/задание.json`.

## Верхний уровень

| Ключ | Обязателен | Что это |
|---|---|---|
| `проект` | да | Сведения для штампа чертежа |
| `комплекс` | нет | Обозначение комплекса, по умолчанию `КСУ1` |
| `объекты` | да | Перечень объектов автоматизации |
| `раскладка` | нет | Явное размещение модулей по секциям и слотам |
| `слот1` | нет | Надписи неизменяемой панели слота 1 |
| `резерв` | нет | Сколько глухих панелей добавить (только при автоматической раскладке) |
| `резервные надписи` | нет | `false` — не подписывать свободные места «Резерв / —» |

## `проект`

| Ключ | Куда попадает |
|---|---|
| `наименование` | Наименование объекта в штампе, оно же имя файлов выгрузки |
| `шифр` | Шифр; из него складывается обозначение документа «<шифр> ВО» |
| `обозначение` | Обозначение документа, если нужно задать вручную |
| `здание` | Графа «наименование здания, сооружения» |
| `стадия` | Графа стадии, по умолчанию `Р` |
| `организация` | Графа организации |
| `разработал`, `проверил`, `контроль`, `гип` | Фамилии в графах подписей |
| `дата` | `ГГГГ-ММ-ДД` |

## `объекты`

Одна запись — один объект или одна точка измерения:

```json
{ "тип": "задвижка", "назначение": "Задвижка ЗД-9", "объект": "РВС-2", "секция": 1 }
```

| Ключ | Что это |
|---|---|
| `тип` | Тип объекта из таблицы в [library.md](../../_Tools/claude-plugins/plugins/asutp-sections/skills/asutp-sections/references/library.md) или `node scripts/library-table.mjs` |
| `назначение` | Первая строка шильда: параметр, позиция аппарата |
| `объект` | Вторая строка шильда: к чему относится (насос, резервуар, контур) |
| `подпись` | Для однострочных шильдов модуля `65` — весь текст одной строкой |
| `секция` | Номер секции (1, 2, …), если объект должен стоять именно в ней |

Ключ `секция` — это решение инженера, а не расчёт: так одна технологическая
группа держится в одной секции, а свободные места остаются осознанно. Объекты
без `секции` добираются по остатку в первый подходящий модуль.

Типы объектов и ёмкости модулей — в справочнике `library.md`. Коротко:
`двигатель` (прямой пуск) — 4 в модуле, `пч` — 4, `задвижка` — 8,
`задвижка-рег` (КР, ЗР, ЭМК) — 4, `уровень` — 8 (по каналам ГАММА-8М),
`индикатор` — 8. Модуль не делится между секциями: 6 насосов с ЧРП — это два
модуля `45` (4 + 2), а не «полтора».

Точка уровня — это **канал**, а не прибор: у ГАММА-8М два независимых канала,
и рядом могут стоять взлив одного аппарата и межфазный уровень другого.

## `раскладка`

Строка — секция, ячейка — тип модуля в слотах 2, 3, 4, 5:

```json
"раскладка": [
  ["уровень", "пч", "задвижка-рег", "задвижка"],
  ["уровень", "пч", "задвижка-рег", "задвижка"],
  ["индикатор", "двигатель", "задвижка-рег", "резерв"],
  ["индикатор", "двигатель", "задвижка-рег", "резерв"]
]
```

Это компоновка реального проекта: в каждой секции по одному модулю уровня, приводов,
регулирующей арматуры и задвижек. Без `раскладки` модули набиваются подряд и
разрезаются по 4 на секцию — годится для первой оценки числа секций, но
распределение по шкафам инженер обычно задаёт сам.

`резерв` или `"00"` в ячейке — глухая панель.

## `слот1`

Панель слота 1 есть в каждой секции: 8 сигнальных лампочек (`L2`…`L9`) и
8 индикаторов (`H11`…`H14`, `H21`…`H24`). По опыту проекта: лампы — дискретная
сигнализация (авария насоса, ПАЗ, ПДВК, уровень Нав/Нмакс), первый ряд
индикаторов — давления, второй — температуры, расходы, положение арматуры.
Лампа держит 17 символов в строке, индикатор — 39.

Массив — по секциям:

```json
"слот1": [
  { "лампы": [{ "назначение": "Авария", "объект": "Насос Н-6" }], "индикаторы": [] },
  { "лампы": [], "индикаторы": [{ "назначение": "Давление", "объект": "Сепаратор Е-9" }] }
]
```

Объект — общая очередь, которая разливается по секциям по порядку: первые
8 лампочек в `SEC1`, следующие в `SEC2`.

Шильд `L1` («Питание ~220В») неизменяемый и в задании не участвует.

## Как считаются секции

1. Объекты группируются по типу; ключ `секция` держит их в своей секции.
2. При заданной `раскладке` модуль набирается объектами своей секции, затем —
   объектами без привязки.
3. Без `раскладки` объекты каждого типа набиваются в модули подряд, модули
   раскладываются по 4 на секцию.
4. Свободные слоты закрываются глухой панелью `00`, свободные места занятого
   модуля подписываются «Резерв / —».
5. Обозначение секции `НТ53.AA.BB.CC.DD` собирается из кодов слотов 2…5.

Скрипт пишет замечания: объекты, которые не поместились в раскладку; строки,
не влезающие в шильд; неизвестные типы. Ни одно из них не исправляется молча.
