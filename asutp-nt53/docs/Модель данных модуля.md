# Как править модель данных модуля

Порядок действий, когда модулю нужно новое поле — например `channels` (каналы
подключения) или что-то ещё. Проверено на этой правке: тип, генератор, проверки,
потребители, документация.

## 0. Сначала различить две модели

| Модель | Где живёт | Нужна ли миграция |
|---|---|---|
| **Модуль** (`ModuleSpec`, `DeviceSpec`, `LabelSpec`, `ChannelSpec`) | `src/library/*.json`, генерируются из `scripts/gen-library.mjs` | **Нет.** Библиотека пересобирается целиком; в проекте пользователя от модуля хранится только код и значения надписей |
| **Проект** (`Project`, `Complex`, `Section`, `SlotInstance`, `ProjectMeta`) | `localStorage` браузера и файлы `.json` у пользователей | **Да.** Поднять `version`, дописать перевод в `normalizeProject` ([src/lib/project.ts](../src/lib/project.ts)) — как при переходе «шкаф → секция» |

Дальше — про модель модуля. Если правится модель проекта, то же самое плюс
миграция и проверка на реальном сохранённом файле.

## 1. Тип в `src/types.ts`

Новое поле делать **необязательным** (`field?: T`): панели заполняются данными
по мере получения рабочей документации, и модуль без поля должен оставаться
валидным. Отсутствие поля означает «данных нет», а не «ноль».

Комментарий над полем — обязательно: единицы, откуда берутся данные, что значит
пустое значение. Модель читают и через год.

```ts
export interface ModuleSpec {
  …
  /**
   * Каналы подключения датчиков, в том числе не выводимые на фасад.
   * Пока заполнены не у всех панелей: данные берутся из рабочей документации.
   */
  channels?: ChannelSpec[]
}
```

## 2. Генератор `scripts/gen-library.mjs`

`src/library/*.json` **править нельзя** — `npm run gen:library` удаляет папку и
собирает заново. Поле заполняется в вызове `add({...})` нужной панели, а если
требует геометрии или повторяется — в типовом блоке (`makeBuilder`, `b.dev`,
`b.cell`, `motorBlock`, `valveBlock03` и прочие).

Заполнять только там, где данные действительно есть. Выдуманные артикулы и
номера клемм хуже пустого поля: они уходят в спецификацию.

Исключение — **каналы подключения**: их заполняет инженер в `docs/каналы/<код>.md`,
генератор только читает файлы (`scripts/channels.mjs`). Канал там — точка
подключения одного внешнего устройства, а не сигнал ПЛК. Если поле относится к
подключаемому оборудованию, ему место в этих таблицах, а не в коде генератора.

## 3. Перегенерировать и посмотреть вывод

```bash
npm run gen:library
```

Строка отчёта по каждой панели показывает, что записалось: приборов, шильдов, а
после этой правки — и каналов.

## 4. Дописать проверку в `scripts/check-library.mjs`

Проверка — часть модели, а не украшение: она ловит опечатки в данных, которых
TypeScript не видит (JSON приходит из генератора). Что проверять для нового
поля:

- уникальность идентификаторов внутри модуля;
- значения из закрытых перечней (тип сигнала, взрывозащита);
- ссылки на другие сущности модуля (`display` → `devices[].id`);
- геометрию, если поле про размеры: выход за панель и наложения.

Если появились новые коды панелей (например исполнение Exd) — нужны фотография
или вид по РД в папке `Модули`, иначе `check-photos.mjs` сообщит о расхождении.

## 5. Пройти по потребителям

`ModuleSpec` читают:

| Файл | Править, если новое поле… |
|---|---|
| [src/library/index.ts](../src/library/index.ts) | …требует нового индекса или фильтра. Загрузку править не нужно: `import.meta.glob` тянет любой JSON |
| [src/components/ModuleView.tsx](../src/components/ModuleView.tsx), [DeviceShape.tsx](../src/components/DeviceShape.tsx) | …должно рисоваться в приложении |
| [src/components/ModuleCatalog.tsx](../src/components/ModuleCatalog.tsx) | …показывается в каталоге или участвует в поиске |
| [src/components/PropertiesPanel.tsx](../src/components/PropertiesPanel.tsx) | …видно в свойствах выбранного модуля |
| [src/export/facade.ts](../src/export/facade.ts) | …должно попасть на чертёж: один код рисует и DXF, и PDF |
| [src/export/labels.ts](../src/export/labels.ts), [bom.ts](../src/export/bom.ts), [spec.ts](../src/export/spec.ts) | …идёт в таблицу надписей, перечень приборов, спецификацию |
| [src/export/pdf.ts](../src/export/pdf.ts) | …нужно в таблицах на листах («Состав секции», «Приборы на фасаде») |
| [src/lib/project.ts](../src/lib/project.ts) | …влияет на значения по умолчанию в экземпляре модуля |
| [scripts/kinds.mjs](../scripts/kinds.mjs) | …меняет правило подбора: ёмкость модуля, адреса шильдов |
| [scripts/plan.mjs](../scripts/plan.mjs) | …участвует в компоновке или в отчёте по секциям |
| [scripts/library-table.mjs](../scripts/library-table.mjs) | …должно быть видно навыку Claude Code. Затем перегенерировать справочник плагина |

Если поле нигде не читается — это нормально на первом шаге: сначала схема и
данные, потребители по мере появления реальных значений.

## 6. Прогнать проверки

```bash
npm run build && npm run check && npm run check:pdf
```

- `build` — типы и сборка;
- `check` — геометрия библиотеки, сверка с папкой `Модули`, регрессия компоновки
  (эталон АКН-2026: 4 секции, 160 надписей);
- `check:pdf` — альбом собирается, содержимое не выходит за рамку.

Если правка затрагивает фасад — сверить глазами: выгрузить PDF и DXF
(`npm run export -- "<проект>" --pdf --dxf`) и проверить чертёж
`npm run check:dxf`.

## 7. Обновить документацию

| Что | Где |
|---|---|
| Формат нового поля, правила заполнения | отдельный файл в `docs/` (например [Каналы подключения.md](Каналы%20подключения.md)) |
| Новый столбец в файлах каналов | `COLUMNS` в [scripts/channels.mjs](../scripts/channels.mjs) и таблица столбцов в `docs/Каналы подключения.md` |
| Короткое описание и ссылка | `README.md` — раздел про библиотеку модулей |
| Договорённость с заказчиком изменилась | `ТЗ.md` |
| Нужны данные от инженера EPLAN | `docs/Замечания к EPLAN.md` — новая строка реестра |
| Навык должен знать о поле | `npm run gen:library-table -- --out="…/references/library.md"` |

## Правила, которые стоит держать

1. Новое поле — необязательное; пустое значит «данных нет».
2. Вычислимое в модели не хранить: обозначение секции, число приборов, суммы —
   считаются на месте.
3. Единицы — миллиметры; начало координат панели — левый верхний угол, ось Y вниз.
4. Данные не дублировать: связь между сущностями — по `id` (как `channels[].display`
   ссылается на `devices[].id`).
5. Разная комплектация одной панели — **разные коды** библиотеки: код входит в
   обозначение секции `НТ53.AA.BB.CC.DD` и в спецификацию.
6. Модель проекта меняется только вместе с миграцией и подъёмом `version`.
7. Артикулы и номера клемм не выдумывать: пустое поле и строка в реестре
   замечаний лучше правдоподобной ошибки в спецификации.
