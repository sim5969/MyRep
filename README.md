# Конфигуратор внешнего вида секций АСУ ТП (НТ53)

Веб-приложение для сборки фасада секции АСУ ТП из типовых вставных модулей.
Техническое задание — [ТЗ.md](ТЗ.md). Текущее состояние — **этап 1**.

## Термины

| Термин | Что это |
|---|---|
| **Секция** | Отдельный шкаф с цоколем 2200 × 600 × 600 и пятью слотами под модули. Обозначается по месту в комплексе: `SEC1`, `SEC2`, … |
| **Комплекс секций управления (КСУ)** | Набор секций, стоящих в один ряд. Обозначение по умолчанию — `КСУ1` |
| **Модуль** (панель) | Вставная лицевая панель слота: двузначный код, приборы и шильды |

Проекты, сохранённые прежней версией (там секция называлась шкафом, а комплекс — секцией),
приводятся к новой схеме при открытии: прежние шкафы становятся секциями `SEC1`, `SEC2`, …,
а комплекс получает обозначение `КСУ1`.

## Что умеет на этапе 1

- Комплекс секций управления из произвольного числа секций, обозначения `SEC1`, `SEC2`, …
- 5 слотов в секции: слот 1 — 400 мм, неизменяемая панель сигнализации и индикации (код `01`); слоты 2…5 — 250 мм.
- Установка модуля перетаскиванием из каталога на слот или двойным кликом по модулю при выбранном слоте.
- Автоматическая сборка обозначения секции `НТ53.AA.BB.CC.DD` из кодов слотов 2…5.
- Редактирование надписей выбранного модуля с контролем длины строки.
- Копия секции (с надписями и без), перестановка, удаление.
- Обмен двух модулей местами вместе с их надписями — перетаскиванием правой кнопкой мыши, внутри секции и между секциями.
- Отмена/повтор, автосохранение в браузере, сохранение и открытие проекта в JSON.
- Показ позиционных обозначений приборов «слот.номер».
- Выгрузка альбома PDF А3 в фирменной рамке ООО «НТ», DXF вида на фасад, таблицы надписей CSV и спецификации XLSX (этап 2).

### Навигация по полотну

| Действие | Как |
|---|---|
| Масштаб | Колесо мыши — к точке под курсором. Кнопки `−` / `+`, клавиши `+` / `−` |
| Вписать в окно | Кнопка «Вписать» или клавиша `0`. Действует и при изменении размера окна |
| Натуральная величина | Кнопка «1:1» или клавиша `1` — 100 % соответствует размеру в миллиметрах на экране 96 dpi |
| Панорама | Средняя кнопка мыши или Ctrl + перетаскивание |
| Прокрутка | Shift + колесо, полосы прокрутки |

### Обмен модулями местами

Надписи принадлежат модулю, а не месту в секции, поэтому при обмене переезжают вместе с ним.

| Действие | Как |
|---|---|
| Перетаскиванием | Нажать правую кнопку на модуле, не отпуская привести курсор на нужный слот, отпустить |
| Через панель инструментов | Выбрать слот, нажать «Поменять местами», щёлкнуть второй слот |

Источник обмена подсвечивается оранжевым пунктиром, допустимая цель — зелёной рамкой.
`Esc` отменяет начатый обмен. Обычный щелчок по модулю только выделяет его.

Обмен допустим, если каждый модуль разрешён в слоте, куда переезжает. Практически это значит:
слоты 2…5 меняются между собой в любой секции комплекса, а панель слота 1 — только с панелью
слота 1 другой секции, поскольку она высотой 400 мм. Обмен пишется в историю — «Отменить»
возвращает и модули, и надписи.

На «Вписать» помещается весь комплекс целиком (для трёх секций это около 9 %),
на «1:1» читаются все надписи на шильдах. Предел увеличения — 400 %.

Из этапа 2 сделано: PDF А3 со штампом, DXF, таблица надписей и спецификация XLSX.
Не сделано: раскладка шильдов под ORACAL (ожидается размер листа плёнки и требуемые зазоры).
Пресеты и серверное хранение — этапы 3–4 по ТЗ.

## Выгрузка

Кнопки «PDF А3», «DXF», «Надписи» и «Спецификация» на панели инструментов. В режиме «КСУ»
выгружается весь комплекс, в режиме «Секция» — только выбранная секция.

### PDF А3

Альбом листов А3 (420 × 297) в **фирменной рамке ООО «НТ»**: рамка, большой штамп 185 × 55,
полосы согласования, метки зон листа и логотип берутся из шаблона организации
`P:/Шаблон AI-пакета ООО НТ/AI/templates/Рамка А3 с большим штампом (ГОСТ_A3_БШ).dxf`.

Шаблон — выгрузка EPLAN: геометрия лежит в блоке `EPLFRAME`, заполняемые графы заданы
определениями атрибутов с тегами свойств EPLAN. Скрипт `npm run gen:frame` переводит его
в данные `src/export/pdf/frame-a3.ts` (линии с толщинами по слоям шаблона, постоянные
надписи, ячейки граф) и готовит логотип `src/assets/logo-nt.png` из
`AI/company/ЛОГОТИП малый.png`. Правится шаблон — запускается скрипт, приложение
подхватывает новую рамку.

Большой штамп идёт на всех листах альбома, номер листа и число листов заполняются
автоматически. Графы «Масштаб» в этом штампе нет, поэтому масштаб печатается рядом
с заголовком вида.

| Лист | Содержание |
|---|---|
| 1 | Вид на фасад комплекса: все секции в ряд, над каждой обозначение `SEC1`, `SEC2`, … и обозначение `НТ53.AA.BB.CC.DD`, справа таблица «Состав комплекса» |
| далее, на каждую секцию | Вид на фасад 1:10 с выносками номеров слотов, таблица «Состав секции» по слотам и таблица «Приборы на фасаде» — наименование, артикул, количество, позиционные обозначения по РД |
| | Таблица надписей секции: слот, количество, строка 1, строка 2, размер шильда. Выводятся только **редактируемые** надписи — то, что задаёт проектировщик; неизменяемые подписи органов управления («Готов», «Стоп PLC») входят в состав модуля. Совпадающие шильды одного модуля сведены в одну строку с количеством, в пределах слота сначала двухстрочные шильды «назначение / объект». Таблица идёт в две колонки и при необходимости переносится на следующие листы |

Масштаб вида на листе комплекса подбирается из ряда ГОСТ 2.302 (1:2 … 1:50) так, чтобы вид
уместился в поле листа и не залез на штамп: для комплекса до трёх секций это 1:10,
до шести — 1:15. Листы секций всегда 1:10.

Графы штампа заполняются из свойств проекта (блок «Штамп чертежа» в панели свойств):

| Графа штампа | Что подставляется | Тег EPLAN |
|---|---|---|
| обозначение документа | поле «Обозначение», по умолчанию `<шифр> ВО` | `4_11090[1]` |
| наименование объекта | наименование проекта, при необходимости в две строки | `4_11090[2]` |
| наименование здания, сооружения | поле «Здание» | `4_11090[3]` |
| наименование чертежа | `Вид на фасад комплекса КСУ1` или `Вид на фасад секции SEC1` | `4_11090[4]` |
| стадия | поле «Стадия», по умолчанию `Р` | `14_10031` |
| лист, листов | номер листа и общее число листов альбома | `4_11000`, `4_11004` |
| организация | поле «Организация» | `14_10015` |
| Разраб., Пров., Н.контр., ГИП | одноимённые поля | `4_40101`…`4_40104` |

Если надпись не входит в графу, кегль уменьшается (ГОСТ 2.304 это допускает), и только
при кегле меньше 1,6 мм строка обрезается многоточием. Таблица изменений и графы
структурных идентификаторов остаются пустыми — они заполняются от руки.

Надписи шильдов выводятся на фасаде в любом масштабе: при 1:10 буква выходит около 0,22 мм —
на бумаге это серая полоса, но текст векторный и читается при увеличении на экране, а на
чертеже видно, что и где написано. Порог по назначению надписи задан в `src/export/pdf.ts`
(`MIN_CAP`): наименования приборов внутри их контуров при уменьшении не рисуются — при 1:10
они только загрязняют чертёж, состав приборов даёт таблица на листе. Читаемые тексты
редактируемых надписей — на листе таблицы надписей; полный перечень шильдов, включая
неизменяемые подписи, — в выгрузке «Надписи». Позиционные обозначения приборов —
в таблице «Приборы на фасаде».

Слоты на листе секции помечены выносками с номерами 1…5 — они связывают вид с таблицей
«Состав секции».

Оформление листа и чертёж пишутся в разные потоки содержимого страницы: так проверка
отличает рамку, которая доходит до кромки листа, от чертежа, который обязан остаться
внутри рамки.

Документ собирается без внешних библиотек ([src/export/pdf/](src/export/pdf/)). Кириллица
выводится вложенным шрифтом **ISOCPEUR Italic** (шрифт типа Б с наклоном по ГОСТ 2.304,
тот же, которым оформлены выгрузки EPLAN) — шрифт вкладывается в файл как CIDFontType2
с кодировкой Identity-H, поэтому текст отображается одинаково на любой машине, при этом
копируется и находится поиском. Замена шрифта — подмена файла `src/assets/isocpeur-italic.ttf`
(нужен TrueType с таблицей `glyf` и разрешённым вложением).

Проверка выгрузки без браузера — модули выгрузки загружаются загрузчиком Vite, поэтому
результат тот же, что в приложении:

```bash
npm run check:pdf
```

Ключи: `--out=путь.pdf` (по умолчанию файл пишется в каталог временных файлов),
`--sections=6` — число секций в проверочном комплексе.

### DXF

Формат R12, единицы — миллиметры, ось Y направлена вверх, начало координат — низ цоколя
первой секции. Кириллица кодируется как `\U+XXXX`, поэтому файл не зависит от кодовой страницы.

| Слой | Содержание |
|---|---|
| `SECTION` | контур корпуса секции |
| `PLINTH` | цоколь |
| `OPENING` | рамка проёма под модули |
| `PANEL` | лицевые панели модулей |
| `DEVICES` | приборы: индикаторы, лампы, переключатели, панели оператора |
| `CUTOUT` | монтажные вырезы в панели: Ø по центру прибора либо прямоугольник |
| `LABELS` | рамки шильдов |
| `TEXT` | надписи на шильдах |
| `POSITIONS` | позиционные обозначения «слот.номер» |
| `DESIGNATION` | обозначение секции `НТ53.AA.BB.CC.DD` и её номер `SEC1`, `SEC2`, … |

Позиционные обозначения вынесены в отдельный слой, чтобы их можно было отключить при печати.
Слой `CUTOUT` содержит только монтажные отверстия и годится для раскроя лицевых панелей.

### Разбор рабочей документации

Панели, для которых есть выгрузка из EPLAN, собираются не по фотографии, а по РД.
Два скрипта переводят листы DXF в координаты панели и в таблицу спецификации:

```bash
node scripts/rd-facade.mjs "Модули/Макросы V25.02 (Platform_2026)/==КД/=ОП/.SEC1/+15/Компоновка электрошкафа/==КД=ОП.SEC1+15&СБ_11.dxf"
```

Ключ `--texts` добавляет все надписи с координатами.

```bash
node scripts/rd-spec.mjs "Модули/Макросы V25.02 (Platform_2026)/==КД/=ОП/.SEC1/+15/Групповая спецификация изделий/==КД=ОП.SEC1+15&СО_23.dxf"
```

Результаты сведены в [docs/Рабочая документация — данные панелей.md](docs/Рабочая%20документация%20—%20данные%20панелей.md).
Всё, что в выгрузке не сходится, попадает в [docs/Замечания к EPLAN.md](docs/Замечания%20к%20EPLAN.md) —
этот список передаётся инженеру как задание на правку проекта.

Проверка выгруженного файла — из корня проекта, файл искать не нужно, берётся самый свежий
`.dxf` из корня проекта или папки загрузок:

```bash
npm run check:dxf
```

Можно указать файл явно; относительный путь ищется в текущем каталоге, корне проекта и папке загрузок:

```bash
npm run check:dxf -- "Новый проект фасад.dxf"
```

### Таблица надписей

CSV в UTF-8 с BOM, разделитель «;» — открывается в Excel без диалога импорта.
Одна строка на каждый шильд: проект, КСУ, секция, обозначение секции, слот, код и наименование
модуля, идентификатор шильда, строки текста, ширина и высота шильда в миллиметрах, кегль,
признак редактируемости. Размеры округлены до 0,1 мм.

Выгружаются все шильды, включая неизменяемые («Готов», «Стоп PLC»): они тоже печатаются.

### Спецификация XLSX

Четыре листа:

| Лист | Содержание |
|---|---|
| «Состав по секциям» | построчно по слотам: секция, обозначение, слот, код и наименование модуля, высота, число приборов и шильдов |
| «Сводная» | по кодам модулей: артикул панели, количество, цена, сумма, итог |
| «Приборы» | сводка приборов по комплексу: артикул, наименование, количество, позиционные обозначения из РД |
| «Надписи» | та же таблица шильдов, что и в CSV |

Цена модулей в библиотеке пока не заполнена, поэтому колонка «Цена» пустая, а «Сумма» и «Итого» —
формулы Excel: достаточно вписать цены, и суммы посчитаются сами. На листах включены закрепление
шапки и автофильтр.

ExcelJS подгружается динамически, только в момент выгрузки, чтобы не тянуть мегабайт при открытии
страницы.

## Командная строка

Кроме кнопок в приложении, выгрузки и компоновка доступны без браузера: модули
приложения грузятся загрузчиком Vite, поэтому файлы получаются те же.

### Компоновка по заданию

```bash
npm run plan -- "C:/Проекты/УПН/задание.json" --out="C:/Проекты/УПН/проект.json"
```

На входе — задание: сведения проекта и перечень объектов автоматизации (насосы,
задвижки, уровнемеры, аналоговые параметры). Формат — [docs/Задание на
компоновку.md](docs/Задание%20на%20компоновку.md). Скрипт раскладывает объекты
по модулям, модули по секциям (4 сменных слота в секции), заполняет надписи и
печатает отчёт: сколько секций, что в каждом слоте, где остался запас, какие
строки не влезают в шильд.

Правило «объект ТЗ → модуль» и адреса шильдов — в
[scripts/kinds.mjs](scripts/kinds.mjs): ёмкость модуля (8 задвижек, 4 насоса
с ПЧ, 4 уровнемера, 8 индикаторов) и то, какой шильд принадлежит какому объекту.
Это единственное место, где живёт соответствие; таблица для навыка и подбор
берут его оттуда.

### Выгрузка документов

```bash
npm run export -- "C:/Проекты/УПН/проект.json" --all --out="C:/Проекты/УПН"
```

Флаги: `--pdf`, `--dxf`, `--csv` (таблица надписей), `--xlsx` (спецификация),
`--all`. Имена файлов — как в приложении: «<наименование проекта> фасад.pdf».

### Проверка правил подбора

```bash
npm run check:plan
```

Прогоняет наборы из `tests/plan/<случай>/` (задание + эталонный проект) через
`plan.mjs` и сверяет каждый слот и каждую надпись. В наборе `акн-2026` лежит
реальная компоновка на 4 секции и 160 надписей — если правка в `kinds.mjs`,
библиотеке или `plan.mjs` меняет результат, проверка это покажет. Команда
входит в `npm run check`.

Обновить эталон осознанно:

```bash
npm run plan -- "tests/plan/акн-2026/задание.json" --out="tests/plan/акн-2026/эталон.json"
```

## Как добавить модуль

Описание панели живёт в [scripts/gen-library.mjs](scripts/gen-library.mjs), а
`src/library/*.json` **создаются генератором** (`npm run gen:library` сначала
удаляет папку). Править нужно генератор, затем `npm run gen:library && npm run check`.
Исключение — каналы подключения: они лежат в `docs/каналы/<код>.md` (см. ниже).

Если модулю нужно не новое значение, а новое **поле** — порядок в
[docs/Модель данных модуля.md](docs/Модель%20данных%20модуля.md): тип в `types.ts`,
генератор, проверка в `check-library.mjs`, потребители, документация.

Структура записи модуля:

```jsonc
{
  "code": "03",                       // код панели по перечню EPLAN
  "name": "Наименование панели",
  "article": "НТ53-03.01",            // артикул лицевой панели по РД, необязательно
  "slotHeight": 250,                  // 250 или 400
  "allowedSlots": [2, 3, 4, 5],
  "price": null,
  "devices": [
    { "id": "1", "type": "indicator", "x": 20, "y": 60, "w": 104, "h": 52,
      "name": "Индикатор цифровой щитовой 104×52",
      "article": "ТРМ1-Щ2.У2.И",      // артикул производителя, необязательно
      "ref": "1HG1",                  // позиционное обозначение по РД, необязательно
      "cutout": { "w": 92, "h": 45 } },
    { "id": "2", "type": "lamp", "x": 200, "y": 100, "w": 20, "h": 20, "color": "yellow",
      "name": "Подсветка переключателя", "ref": "1VD3",
      "builtIn": "1" }                // прибор внутри прибора «1»: без выреза и контура
  ],
  "labels": [
    { "id": "L1", "x": 8, "y": 44, "w": 124, "h": 15, "lines": 2, "maxChars": [24, 24],
      "default": ["Параметр", "Объект"], "editable": true, "box": true,
      "align": "center", "fontSize": 3.2 }
  ]
}
```

Шильд — прямоугольная ячейка с рамкой (`box: true`). Соседние ячейки с общей границей
образуют полосу надписей, как на реальных панелях. Кегль можно не указывать: по умолчанию
он равен 0,6 высоты строки ячейки — так же, как на натурных панелях. Текст длиннее ячейки
автоматически поджимается по ширине, чтобы не выходить за рамку, а счётчик в панели свойств
показывает предел длины строки. Приборы типа `device` могут иметь
поля индикации: `"displays": 2, "displayColor": "#7fd4ea"`.

Типы приборов: `indicator`, `lamp`, `switch`, `opPanel`, `meter`, `device`.
Цвета ламп: `green`, `red`, `blue`, `yellow`, `white`.
Поле `cutout` хранит монтажный вырез — прямоугольный (`{ "w": 92, "h": 45 }`) или круглый
(`{ "d": 22.5 }`); в DXF он выгружается на слой `CUTOUT`. Поля `article` и `ref` берутся из
рабочей документации и выводятся на листе «Приборы» спецификации.

Поле `builtIn` описывает прибор внутри прибора — так задана подсветка переключателя:
она входит в спецификацию, но своего монтажного отверстия не имеет, на фасаде рисуется
полупрозрачной линзой поверх рукоятки, а в DXF отдельным контуром не выводится.
Проверка наложений такие пары пропускает.

## Каналы подключения

Кроме приборов на фасаде модуль описывает **каналы подключения** — точки, к
которым снаружи подключается оборудование. Канал — это одно устройство, а не
сигнал ПЛК: станция с преобразователем частоты — один канал, манометр — один
канал. Сигналы внутри канала не расписываются, а даются сводкой, из которой
считается загрузка модулей ПЛК. Часть каналов на лицевую панель не выводится
(манометры, термосопротивления подшипников) — они не дают ни приборов, ни
шильдов, но занимают входы ПЛК.

Каналы заполняет инженер в файле `docs/каналы/<код>.md`, по одному на панель.
Имя файла — только код: `45.md`. Таблицу с данными парсер узнаёт по первому
столбцу `Канал`:

```markdown
| Канал | Устройство | Что подключается | Объект | На фасаде | Сигналы | Ex | Клеммы | Вход ПЛК | Назначение |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| ПЧ1 | ПЧ | ПЧ ABB | 1 | да | 2 AI, 4 DI, 4 DO | нет | 1XT1 | AI1, DI1, DO1 | Станция с ПЧ, насос Н-1 |
| ЭКМ1 | ЭКМ | Электроконтактный манометр | 1 | нет | 1 DI | | XT4 | DI2 | Давление, насос Н-1 |
```

Столбцы читаются по названию, а не по месту. `Устройство` — из закрытого списка
(`ПЧ`, `ЭКМ`, `датчик`, `прибор`, `задвижка`, `двигатель`). `Объект` — номер
объекта модуля, тот же, которым оперирует правило подбора в
[scripts/kinds.mjs](scripts/kinds.mjs); через него канал связан с блоком фасада
и его шильдами. Разбор проверяется командой `npm run channels`, дальше
`npm run gen:library && npm run check`.

Каналы заполнены у всех панелей библиотеки, кроме глухой, `104` и `41` (описаны по
фотографии, каналов пока нет); у панелей `303` и `345` — по аналогии с `03`
и `45`, без документации; у панелей `04` и `304` (исполнение `04` на три
привода) — только объекты и что подключается, без состава сигналов: рабочей
документации на них в выгрузке нет. Разная обвязка одной панели (Exi с барьерами
против Exd без них) — это **разные коды** в библиотеке: код входит в обозначение
секции и в спецификацию. Формат, правила и что ещё не сделано —
[docs/Каналы подключения.md](docs/Каналы%20подключения.md), образцы —
[docs/каналы/45.md](docs/каналы/45.md) и [docs/каналы/02.md](docs/каналы/02.md).

## Примечания

- Печатные формы, которым нужна рамка по ГОСТ, берут её из шаблона AI-пакета ООО «НТ» (`AI/templates`), а не вычерчивают по стандарту заново: рамка переводится в данные скриптом `npm run gen:frame`.
- Реквизиты и логотип организации — только из `AI/company/` шаблона AI-пакета.
- Надписи наносятся печатью на плёнке ORACAL с защитной прозрачной плёнкой сверху; на этапе 2 таблица надписей и контуры обрезки выгружаются отдельно.
- Проект может находиться на сетевом диске — в `vite.config.ts` включён polling для отслеживания файлов.
